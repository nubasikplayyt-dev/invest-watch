# Критерии консервативного портфеля

Источник истины для агента. Оценка строго механическая: только факты и эти критерии, без мнений агента и аналитиков. Каждое событие оценивается по этим пунктам. Формулировки — владельца портфеля, пороги в разделе «Цена входа» помечены, где это расчётное допущение.

## Цель
Портфель бумаг, которые постоянно платят (в идеале — растущие) дивиденды, не боятся инфляции, кризисов и девальвации рубля, управляются хорошим менеджментом и принадлежат умным мажоритариям с хорошей политической крышей. Срок удержания — «пусть внукам достанется». Продажа — только когда событие инвалидирует один из критериев. Движение цены само по себе поводом для продажи не является.

## Критерии качества
| Код | Критерий | Что проверять |
|---|---|---|
| C1 | Вечная тема | Бизнес, нужный людям и 500 лет назад. Стартапы, хайтек, IT, авиаперевозки — нет. |
| C2 | Брутально простая модель | Скучный, понятный, устойчивый к кризисам бизнес (шахта, «Кока-кола»). |
| C3 | Политическая крыша | Реальная способность компании не обанкротиться при кризисе и ошибках. Госучастие само по себе ≠ хорошая крыша. |
| C4 | Хороший менеджмент | Анти-пример — менеджмент Аэрофлота. |
| C5 | Реальный, умный мажоритарий | Не номинальный, вменяемый, с хорошей крышей. |
| C6 | Желание и возможность платить | Низкий долг, стабильный доход, payout не слишком высокий и не слишком низкий. Нет дивидендов/малые дивиденды или нет прибыли → отказ. Рост — опционально. |
| C7 | Pricing power | Только для потребительских компаний: повышать цены без прямой зависимости от госрегулирования. |
| C8 | Экспортёр (плюс) | Для российских бумаг — желательный, но не обязательный плюс: хедж от девальвации. |

## Цена входа
| Код | Правило |
|---|---|
| P1 | Не покупать и не докупать, если текущая дивдоходность ниже порога. Пороги по рынкам — в `config/watchlist.json → markets[].yield_floor_pct`: USD ≈ 1% (порог владельца), RUB 5% (допущение, принято владельцем), HKD/CNY 3% (тот же расчёт, что для рубля: 1% + страновая премия Китая; принят владельцем). |
| P2 | Для сырьевых компаний чистый фильтр по доходности не работает: смотреть нормализованную доходность при средней за цикл цене сырья и фазу товарного цикла. Пик цикла + высокая доходность = ловушка. |
| P3 | Недвижимость/ЗПИФ: интересен дисконт ≈10% к СЧА («критерий Штернлихта»), ≈50% — особенно интересен («критерий Crimson»). Меньший дисконт или премия допустимы при высокой доходности — не ниже типичной дивдоходности акций **или** облигаций AA в той же валюте. Достаточно выполнения любого из двух сравнений. |

## Фонды недвижимости (ЗПИФ, REIT) — дополнительные критерии
Применяются к бумагам `kind: real_estate` вместе с C1–C8 и P1–P3. В консервативную часть идут только фонды категории Core или Core Plus. Если категорию нельзя чётко определить по материалам фонда (раскрытие УК, отчёты, презентации), фонд не рассматривается: Z1 = `fail`.

Категории объектов:
| Категория | Локация | Арендаторы | Здание | Закредитованность |
|---|---|---|---|---|
| Core | Prime (центр Москвы — офисы, ритейл; близко к МКАД — склады) | Крупные, стабильные, с рейтингом A и выше или эквивалентом, долгосрочные договоры | Свежий класс А | 0–40% (владелец предпочитает 0–30%) |
| Core Plus | Очень хорошая, не элитная (центр города-миллионника, КАД Петербурга) | Хорошие, не федеральная элита | «Старенький» класс А | 40–60% |
| Value Add | Сильно не дотягивает хотя бы по одному параметру (провинция, класс C, вакансия, слабые арендаторы) | | | > 60% |
| Opportunistic | Флиппинг, финансирование стройки, «построить и продать», нет текущей доходности | | | |

| Код | Критерий | pass | fail |
|---|---|---|---|
| Z1 | Категория | Core или Core Plus по таблице выше | Value Add, Opportunistic, или категорию нельзя определить |
| Z2 | Прозрачность | Один фонд = один объект; или один тип объектов в однотипной локации; или регулярное раскрытие портфеля (локации, WAULT, rental reversion, стратегия). Известны адреса, класс, арендаторы, условия договоров | «Мешок» объектов без раскрытия |
| Z3 | Арендаторы и договоры | Известны арендаторы, срок договора, механизм индексации (ИПЦ, «пол», «потолок»), сроки пересмотра ставки | Арендаторы или условия неизвестны; короткие договоры без индексации |
| Z4 | Аренда связанным лицам | Нет или раскрыта и в рыночных условиях | Доходность подтянута договором со структурой своей группы |
| Z5 | Финансовая модель | УК публикует детальную модель выплат (по годам/месяцам, индексация, расходы, резервы на ремонт, кредит, допэмиссии) | Модели нет |
| Z6 | Менеджмент УК | Подробные отчёты и презентации; задокументированный положительный опыт таких же фондов (тот же тип и класс объектов) | Нет отчётов и нет опыта аналогичных фондов |
| Z7 | Конфликт интересов | УК не аффилирована с девелопером, чью продукцию продаёт | УК фактически продаёт объекты своего девелопера → `warn` |
| Z8 | «Банковский» фонд | Небанковская УК | Банковская УК с банковским брендингом → не отказ, но `warn` и особо строгая проверка Z1–Z6 |
| Z9 | Рост выплат | Выплаты растут; есть индексация; потенциал rental reversion | Выплаты не растут, индексации нет |
| Z10 | Ликвидность | Только метрика (средний дневной оборот). Не отказ: позицию держать очень долго; вход — при допэмиссиях паёв | — |

Типы недвижимости (учитывать при оценке Z1, Z3, Z9): стрит-ритейл — низкая зависимость от экономики, быстрая передача инфляции, почти нет reversion, сильный оверпрайс; склады — низкая зависимость (только Core/Core Plus), индексация по договору, reversion от малого до +30–100%; офисы — высокая зависимость от экономики и менеджмента, приоритет — премиальная Москва; ТЦ — высокая зависимость, решает менеджмент; отели, рентное жильё — не брать (Z1 = `fail`); light industrial и специализированная — высокий риск (Z1 не выше `warn`).

Данные брать у УК и эмитента (сайт УК, правила фонда, отчёты, раскрытие), не из скринеров и не из брокерских приложений.

## Value & Income — приоритет покупки (R1–R5)
Не отсеивают бумагу, а расставляют очерёдность покупок среди прошедших C/P (и Z для фондов). Бумага, прошедшая основные критерии, подходит и без R3–R5.

| Код | Критерий | Как применять |
|---|---|---|
| R1 | Стабильность текущего дохода | Ровные выплаты год к году/квартал к кварталу — плюс к приоритету, рваные или с пропусками — минус. Ради стабильности допустима меньшая доходность |
| R2 | Защита от инфляции | Доход растёт с инфляцией (индексация аренды, pricing power, экспортная выручка) — плюс. Облигации и другие долговые инструменты в основу портфеля не берутся |
| R3 | Income reversion (фонды недвижимости) | Разница между арендой по договору и рыночной арендой, график перезаключения договоров, доля договоров, обновляемых в ближайшие 2–5 лет. Больше и ближе — выше приоритет. Свежий договор или перезаключение через 5+ лет — около нуля. УК не раскрывает график договоров — красный флаг (Z2/Z6 не выше `warn`) |
| R4 | «Невидимый» рост дохода (акции) | Проект, который с высокой вероятностью будет реализован и даст скачок доходов (своё производство, новые точки, месторождение, госпиталь), а до запуска больше 2 кварталов — плюс к приоритету: рынок «старой экономики» учитывает такое в цене лишь за 1–2 квартала. Нужны факты: решение о проекте, сроки, финансирование, ход стройки |
| R5 | Дивиденды при R4 | R4 + хорошие или хотя бы терпимые дивиденды сейчас → высший приоритет. R4 без дивидендов — не для консервативной части |

Шкала `buy_priority`: «высокий» — проходит C/P(/Z) и есть R4+R5 или значимый близкий R3; «средний» — проходит C/P(/Z), R1 и R2 в порядке; «низкий» — проходит с оговорками (`warn`); «не покупать» — есть `fail`. Спекулятивные идеи — не больше 10% портфеля (вне шкалы).

## Индивидуальные исключения и допущения владельца
- **ФосАгро:** пауза в дивидендах из-за кризиса (сера, ставка, долговой капекс) прощается. Допущения владельца: сера нормализуется до уровня, выгодного для производства удобрений; менеджмент больше не планирует наращивать долг. Контроль: чистый долг и дивиденды в годовом отчёте за 2026 г.
- **Курс:** владелец ожидает движения USD/RUB к ~100 ₽.

## Правило чтения критериев
Если в критерии стоит «и/или» или «или», условие выполнено при выполнении любой из частей. Не требовать обе.

## Шкала оценки события
- `pass` — событие подтверждает критерий.
- `warn` — критерий под давлением, нужно наблюдение.
- `fail` — критерий инвалидирован → кандидат на продажу/отказ от покупки.
- `n/a` — событие критерий не затрагивает.
