# Промт для Claude Code: мини-приложение «Портфель по критериям»

Скопируй всё, что ниже линии, в Claude Code, открытый в папке нового проекта.

---

Собери Telegram Mini App с ботом для уведомлений. Приложение показывает сводки, которые агент мониторинга пишет в GitHub-репозиторий `<OWNER>/<REPO>` (подставлю сам). Сначала прочитай этот репозиторий: `config/watchlist.json`, `schema/event.schema.json`, `CRITERIA.md`, `data/*/status.json`, `data/*/events.jsonl`, `feed/feed.json`, `digests/*.md`. Это единственный источник данных: приложение только читает его, ничего не пишет туда.

## Что должно получиться

### 1. Главный экран — разделы по странам
- Разделы берутся из `config/watchlist.json → sections[]`. Сейчас там один раздел «Российские акции» (`id: ru`).
- Каждый раздел — заголовок с флагом страны и сеткой кнопок.
- Каждая бумага — отдельная кнопка-карточка: логотип, тикер, короткое имя и цветной бейдж вердикта из `status.json` (`buy_zone` — зелёный, `hold` — синий, `watch` — жёлтый, `do_not_buy` — серый, `sell_candidate` — красный). На карточке точка-индикатор, если есть непрочитанные события с `notify: true`.
- Сверху — лента «Важное»: последние события с `importance: critical|high` из `feed/feed.json`.

### 2. Экран бумаги (по нажатию на кнопку)
- Шапка: логотип, имя, тикер/ISIN, вердикт, дата обновления.
- Таблица критериев C1–C8 и P1–P3 из `status.json`: статус-иконка (pass/warn/fail/n/a) и пометка. Расшифровка кода по тапу — текст из `CRITERIA.md`.
- Блок «Что отслеживаем» — поле `watch` из `status.json`.
- Лента событий из `events.jsonl`, новые сверху: дата, тип, важность, заголовок, сводка, ключевые метрики (`metrics`) чипами, источники ссылками. Фильтр по типу события (отчёты, дивиденды, долг и т. д.).
- Отдельная вкладка «Дивиденды»: все события `type: dividend` таблицей.

### 3. Добавление бумаг и разделов — без изменения кода
- Новая бумага = новая запись в `assets[]` нужного раздела `watchlist.json` + папка `data/<id>/`. Приложение подхватывает её само.
- Новый раздел для другой страны = новый объект в `sections[]` (`id`, `title`, `country` в ISO-3166, `currency`, `yield_floor_pct`). Флаг рисуй по коду страны.
- Логотипы: файл по пути из поля `logo` в репозитории; если его нет — сгенерированная заглушка (круг с первыми буквами тикера, цвет по хэшу тикера). Сделай это сразу, логотипов в репозитории пока нет.
- В README опиши оба сценария пошагово.

### 4. Уведомления
- Бот в Telegram. Пользователь жмёт /start, и бот запоминает его chat_id.
- GitHub Action в моём репозитории данных (`.github/workflows/notify.yml`): на каждый push в `main` находит новые строки в `data/*/events.jsonl` с `notify: true` и отправляет их боту через Telegram Bot API (`sendMessage`, разметка HTML: эмодзи важности, бумага, заголовок, 1–2 строки сводки, кнопка «Открыть» с deep link `startapp=<asset_id>` прямо в экран бумаги).
- Токен бота и chat_id — только в GitHub Secrets (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`), нигде в коде.
- Команды бота: `/mute <asset_id>` и `/unmute <asset_id>` для отключения уведомлений по отдельной бумаге; список заглушенных хранится в простом JSON-файле на стороне бота. Если для этого нужен сервер, используй Cloudflare Worker с KV и опиши деплой в README.

### 5. Техника
- Фронтенд: Vite + React + TypeScript, `@telegram-apps/sdk-react`, тема берётся из Telegram (светлая/тёмная), вёрстка под ширину телефона.
- Данные: читать через `https://raw.githubusercontent.com/<OWNER>/<REPO>/main/...`. Если репозиторий приватный — через небольшой прокси на том же Cloudflare Worker с fine-grained токеном только на чтение (секрет воркера, не во фронтенде). Кэш 5 минут, кнопка «Обновить».
- Валидация данных по `schema/event.schema.json` (zod или ajv). Битая строка не роняет экран: пропускается с пометкой в консоли.
- Хостинг фронтенда: GitHub Pages через Actions.
- Язык интерфейса — русский. Даты в формате «30 окт 2026».
- Без аналитики, трекеров и сторонних шрифтов.
